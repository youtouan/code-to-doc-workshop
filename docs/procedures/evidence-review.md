# 手順書：根拠の読み直し（evidence-review）

custom agent `evidence-reviewer`（`.github/agents/evidence-reviewer.agent.md`）を使えない環境で、同じ読み直しをするための手順書です。草案を書いたセッションとは別の、新しいセッションにこのファイルを添付して使います。

## 目的

As-Is 文書や ADR の草案が引用している根拠を読み直し、主張を批評する。どの指摘を採るかは人が決める。

## 入力

- 対象の草案（例：`docs/as-is/order-import-module-map.md`）
- 範囲と、読む人
- 草案が引用している根拠（コードの行、`docs/as-is/observations.md` の観察、実行したテスト）

## 手順

1. 草案から主張を1つずつ取り出し、引用先を開いて読む。
2. 次の点を確かめる。
   - 引用した行が、その主張を支えているか（行は合っていても、主張が広すぎないか）
   - 却下や失敗の単位（行、グループ、実行全体）と、集計の結果を正しく書いているか
   - 本文と Mermaid の図が食い違っていないか
   - 範囲の中に、明らかに読み落とした経路がないか
3. 表にまとめる。列は「主張」「根拠」「問題または不確かな点」「修正案」。確かめた食い違いと、未解決の疑問は分けて書く。
4. 最後に、読んでいない範囲（見えていないところ）を書く。

## 出力

チャットの表だけ。ファイルは変えない。指摘の採否は Decision Owner が決め、採否表の Reason に書く。

## ルール

- 読むだけにする。ファイルを変えない、コマンドを実行しない、ほかのエージェントに任せない。
- エージェントやモデルが同意しても、証明にはならない。どの指摘を採るかは人が決める。
- Free ではモデルを選べない（Auto だけ）。草案を書いたセッションとは別の新しいセッションで読ませ、文脈を引き継がないようにする。

## 止める条件

- 指摘と、読んでいない範囲がはっきりしたら止める。
- 時間が限られているので、指摘は重要な順に6件までにする。

## 確かめ方

この手順では、コマンドを実行しない。人が表の根拠を開き、指摘が正しいかを確かめる。
